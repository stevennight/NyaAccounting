# Nya 记账

本地优先的个人消费记录工具。它关注“这个月花了多少、还能花多少、钱花到哪里”，不维护钱包余额，也不跟踪基金等资产的每日市值。

## 已实现

- 截图和文字可单独或组合录入
- Android/Web 均支持一次选择多张截图，每张可单独补充文字；AI 识别后逐笔核对保存，失败项会排到最后并可单独重试
- Android 安装包可在系统无障碍设置中启用“当前页面截图”，再从通知栏直接截取支付宝等页面并进入录入页
- 通过 OpenAI 兼容接口提取金额、日期、商户、分类、支付渠道和实际扣款工具
- AI 只生成草稿，保存前必须由用户确认
- 分类和子分类可在设置中新增、改名和调整，AI 会从当前分类中选择
- 商户与消费内容分开保存；备注仅由用户手动填写，不由 AI 生成
- 手动录入、账目编辑、重复记录提醒
- 固定支出与订阅可新增、编辑、停用和删除，并可按计划预留预算
- 实际扣款可自动或手动关联固定项目，避免同一笔金额重复预留
- 月度预算、分类占比、商户排行和六个月趋势
- 支出、退款、转账、还款、投资等交易类型采用不同统计规则
- 多币种账目保留原币种；未配置汇率时，外币不会混入默认币种统计
- 本地 JSON 备份、导入和示例数据

## 运行

项目使用 Expo SDK 57。

```powershell
npm install
npm start
```

开发服务器会持续监听并占用当前终端，这是正常行为；按 `Ctrl+C` 停止。

Web 开发：

```powershell
npm run web
```

代码检查和测试（包含领域规则与 AI 接口兼容回归）：

```powershell
npm run check
npm run build:web
```

## AI 配置

在应用的“设置”中填写：

- OpenAI 兼容 API 地址
- 支持图片输入和结构化 JSON 的多模态模型
- 思考级别（兼容模式、关闭或不同推理强度）
- 个人 API Key

Android 和 iOS 使用系统安全存储保存 API Key。Web 开发版只能保存在当前浏览器资料中，因此不建议在公共设备上保存 Key。

关闭“发送截图”后，应用只会发送文字。原始截图只作为临时文件使用，不会写入账本备份。

“思考级别”选择“自动（兼容）”时不会发送 `reasoning_effort`，由模型使用默认值；选择其他级别时会显式发送对应参数。GPT-5.6 默认是中等思考，截图记账可优先尝试“关闭”或“低”以减少等待时间。如果接口明确拒绝该参数，应用会移除参数重试一次，并按 API 地址与模型缓存兼容性结果 7 天。

## 数据与服务端

账目、预算和设置默认只保存在本机，不需要自建服务端。支付渠道和信用卡等信息只是每笔账目的标签，不会参与余额对账。

需要换手机时可导出 JSON 备份再导入。只有未来增加多设备自动同步时，才需要服务端或云存储。
